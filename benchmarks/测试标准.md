# 测试标准

本项目所有性能测试按本文件执行。它定义"什么算合格"。

本文件分两层：

- **通用要求** —— 与具体机器、模型无关的方法学约束
- **本项目取值** —— 本机 + 本引擎下的具体选择（标注为「本项目」）。**换机器或换引擎必须重新确定**

---


## 1. 必须记录的元数据

绝大多数由 `measure.py` 自动写入运行 json，不需要手填：

| 项 | 字段 |
|---|---|
| 代码版本 | `provenance`（commit + 是否有未提交改动） |
| 引擎配置 | `overall.engine`（batched_tokens / max_num_seqs / max_model_len / page_size / 页数 / KV 容量） |
| 模型与框架 | `model` / `env`（torch、CUDA 版本） |
| 负载 | `workload_config` / `workload_desc` |
| 仪器与暖机 | `gpu_sample` / `warmup`（含预热期频率轨迹） |
| GPU 状态 | `env.gpu_before` / `gpu_after` |

**频率必须记录。** SM 频率随负载与电源状态大幅变化，不记录就无法判断两次运行是否处于同一硬件状态、能不能比。

**环境固定项（写在本文件里）：** **本项目** = WSL2 Ubuntu 22.04 / Python 3.12.14 / torch 2.9.1+cu128 /
CUDA 12.8 / flash-attn 2.8.3 / triton 3.5.1 / RTX 4060 Laptop 8 GB（sm_89）/ Qwen3-0.6B。

## 2. 仪器配置（必须冻结）

| 项 | 本项目取值 | 说明 |
|---|---|---|
| GPU 暖机秒数 | 45 | 见 §3 |
| 暖机期间在跑条数 | 32 | 保证"一直有活干" |
| 判稳阈值 | 60 MHz | 见 §3 |
| 运行中 GPU 采样间隔 | 关（0） | 见下 |

**为什么关运行中采样**：频率信息在暖机段已经拿到，而暖机段在**计时区之外、不污染测量**；
正式测量再采一遍没有额外信息，只多一个未知扰动。代价是运行中掉频看不见，只剩跑前/跑后两个采样点。

**同一批「改前 / 改后」必须用完全相同的仪器配置，中途不得更改。**

---

## 3. 暖机（两段，各管一件事）

**第一段 · 引擎层**：由 `LLM(...)` 构造过程完成 —— 跑一次最大长度的 prefill，并捕获各档 CUDA graph。
管的是 kernel 编译与显存分配，不需要干预。

**第二段 · GPU 层**：用**持续饱和负载**拉升频率，期间定期采样频率。

- 必须"一直有活干"：频率靠持续负载维持，引擎一排空就掉回低功耗状态
- **判稳用"窗口前后两半的频率中位差 ≤ 阈值"**，不用极差 —— 单次运行内部的频率摆幅可达数百 MHz，极差永远判不出稳定

**验收：每次运行都必须检查 `warmup.ramp.stable` 是否为 `true`。为 `false` 就调大暖机秒数重跑该发。**

---

## 4. 运行点选择

**唯一判据：`waiting` 队列基本为零。** 跑完读逐步记录的 waiting 列：

| 观察 | 判定 |
|---|---|
| 全程为 0，或个别步非零但**不随时间上升** | ✅ 有效 |
| 后段明显大于前段 | ❌ 队列在涨，仍属过载 → 降低 λ |

**不得用以下方式选点：**

- 看"吞吐有没有涨"判断过载 —— 过载前后吞吐只差几个百分点，看不出来
- 选"刚饱和、最有代表性"的点 —— 接近满载时等待时间的方差发散，不可复现
- 把"发生了抢占"当作负载够重的标志 —— 抢占是过载现象，不是基线的要求

**本项目采用两个运行点**（换机器或换负载都必须重新确定）：

| 点 | 角色 | 用来测什么 |
|---|---|---|
| **λ=1.0** | 干净点（排队为零） | TTFT、ITL 尾部、吞吐、固定开销类改动 |
| **λ=4.0** | 饱和点（队列持续增长、抢占活跃） | 抢占、排队、prefill 效率、KV 与量化类改动 |

**为什么只要两个**：一个运行点只能灵敏地反映"在该点上占比大的东西"，用错点会得出错的优先级。
轻载点里 λ 再取大会让延迟尾部抖动显著放大（得不偿失）；饱和点里 λ 再取大买不到更多抢占，
只买到更差的延迟。

### 4.1 小 n 探路不能用来判定边界

探路（小 n）只能**筛掉明显不合适的值**，不能在边界附近下结论。

**候选运行点必须在真实 n、且用最重的种子上验证过后才能采用。** 两个原因：

1. 到达次数少时，队列出不出现受随机波动主导，方向甚至不单调
2. 同一个 λ，**跑得越久越容易撞上到达高峰形成队列**

## 5. 负载与种子

**负载（本项目，冻结）**：四种形状按固定配比混合，输入/输出长度各自按区间抽
（短问短答 / 短问长答 / 长问短答 / 长问长答）；纯合成随机 token id；
`ignore_eos=True` 强制跑满指定长度（否则每次总 token 数不同，数字不可比）；泊松到达，
到达间距整体缩放使样本平均到达率正好等于 λ。

**任何改动负载都必须重新立基线。基线冻结前不得改。**

**种子：**

- **一个种子 = 一组**；组内连跑 N 次 → **组内差 = 重复性（噪声底）**
- **换种子 = 换一份不同的负载**，不是同一份负载的重复 —— 输出总 token 量本身就有百分之几的差异
- **不要把组内差和跨种子差混成一个"噪声底"** —— 两者来源不同
- 运行顺序：**外层种子、内层重复**
- 次数至少 2。**`--repeats 1` 时"重跑差异"会显示 0.00%，那不是噪声为零，是没有样本**

---

## 6. 对比协议

**必须同种子、同一口气交错跑**：改前/改后/改前/改后……，用同轮的数据相减。

- ❌ **跨会话比**（"上次的基线 vs 今天"）—— 机器状态漂移会掩盖真实效果
- ❌ **跑完两批再比**（比中位数、逐种子配对都一样）—— 关键在**交错**，不在统计量
- ✅ 对比做在**延迟与步耗时**上；**吞吐只在同种子内比**（原因见 §5）
- ✅ **交错必须至少有一次反序**（改后在前）。固定顺序下，"分支的效应"与"顺序造成的假象"分不开 ——
  实测中反过来跑一次、结论就翻的情况真实发生过

## 7. 判读门槛

**门槛从组内重复性现算，且随运行点与仪器配置变化 —— 不得沿用旧门槛。**

门槛放得太松会把噪声当效果；收得太紧会把真实效果当噪声。**本项目当前门槛**（保守取最坏情况）：

| 指标 | 门槛 |
|---|---|
| ITL p50 | > 2% |
| ITL p99 | > 10% |
| TTFT p50 / prefill p50 | > 30% |
| 输出吞吐（仅同种子） | > 4% |
| 抢占次数 | > 30% |
| 最大并发 | > 5% |
| `ITL max` / `重算 token` | **百分比判据不适用**，见 §7.1 |

### 7.1 两个极值型指标：百分比判据不适用

| 指标 | 为什么 |
|---|---|
| `ITL max` | **单点极值** —— 最坏的那一根定它，一次调度延迟或系统抖动都算数 |
| `重算 token` | 等于「prefill 处理量 − prompt 总量」，**两个大数相减** —— 值小时相对误差被放大 |

**规则：这两个指标只看倍数。** 变化倍数低于以下阈值时不引用：`ITL max` < **2 倍**、
`重算 token` < **5 倍**。（注：`重算 token` 的比值噪声主要出现在**值小**时；值到数千量级时反而相当稳。）

### 7.2 部分指标只能在同种子内比

**抢占次数、重算 token、TTFT p50、ITL max** 这几项的**跨种子散布远大于组内重复性** ——
换种子等于换负载，而抢占对 KV 压力极敏感。**跨种子看这几项等于看噪声。**

---

## 8. 禁止事项

1. 不得中途更改仪器配置（采样 / 暖机 / n / λ）后继续与前面的数据比较
2. 不得把饱和点当作**唯一**基线（那里的 TTFT 与吞吐不可用）
3. 不得跨会话直接比较
4. 不得跨种子比吞吐
5. 不得用单个种子的结果宣称改动有效
6. 不得在基线冻结前更改负载
7. 不得把"观测不污染 `step_ms`"当成"观测不影响结果" —— 两者不是一回事

---

## 9. 标准命令

在 WSL 里执行。

```bash
# 探路（只能在明显太轻/太重时下结论，见 4.1）
python -m benchmarks.measure --tag probe --seed 2 --n 64 --lam X

# 基线 / 对照（同一口气里跑完 N 个种子 × M 次）
python -m benchmarks.sweep --tag <名字> --seeds 0 1 2 --repeats 2 --lam 1.0 --n 256
```

**tag 不得与已有数据重名** —— `sweep` 会直接覆盖 `{tag}_s{seed}_r{次数}.json`。

结果的呈现与各阶段的具体数字见 [`结果与复现.md`](结果与复现.md)。
